# TaskForge — Phase 6.11: Strict deterministic CI and release artifact enforcement

**Change scope:** make the reviewed npm lockfile mandatory in CI, use `npm ci` unconditionally, and require the static release-artifact preflight. No deployment or production resource access.

## Verified prerequisite

- PR #31 adds an authentic npm v3 `package-lock.json` generated by the trusted GitHub Actions runner.
- The isolated [lockfile import workflow](https://github.com/pravin99c/scalable-task-manager/actions/runs/45036628802) passed checksum verification, `npm ci`, TypeScript, Vitest and Vite build.
- The full [PR #31 CI run](https://github.com/pravin99c/scalable-task-manager/actions/runs/45036727130) passed. **PR #31 is not yet merged into `development`** at this phase's start.
- This Phase 6.11 branch is based on PR #31, not the old lockfile-free development HEAD.

## CI changes

1. Fail if `package-lock.json` is missing or empty.
2. Run `python3 scripts/validate_npm_lockfile.py` against the committed dependency declarations, HTTPS origins, and integrity fields.
3. Run **only** `npm ci --no-audit --no-fund` for dependency installation. The old silent `npm install` fallback is removed.
4. Fail if required static release artifacts are missing using `python3 scripts/release_quality_gate.py --strict`.
5. Remove the now-unnecessary "generate and upload package-lock" artifact steps. All Laravel, React, MySQL, Playwright, Sail, queue, scheduler and Python unit tests remain enabled.

These gates establish that a deterministic lockfile and supporting release documents exist, **not** that production infrastructure is ready, that all dependencies are secure, or that an encrypted backup restore has been performed. They do not use application credentials or production data.

## Dependency advisory policy

CI continues to emit Composer and npm advisory **warnings** because an upstream registry outage or a vulnerability finding should be triaged explicitly rather than making ordinary application tests falsely seem broken. Before any release, the maintainer MUST run:

```bash
bash scripts/audit-dependencies.sh
php scripts/production-preflight.php /secure/path/to/candidate.env
php artisan taskforge:readiness-check
```

An unresolved high/critical advisory must be remediated or explicitly risk-reviewed and approved before release. Never describe a green CI build as a vulnerability-free security certification. Do not deploy when advisory review is incomplete.
